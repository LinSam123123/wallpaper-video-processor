# Make Video Wallpaper

Use the bundled wrapper to invoke the AI Video Wallpaper CLI without depending on the caller's current directory. It prefers the installed console launcher or a project build and falls back to the bundled CLI; it never invokes the GUI executable as a console program. Read [references/parameters.md](references/parameters.md) before creating a JobSpec or interpreting a failure.

## Workflow

1. Run `scripts/invoke-wallpaper-video.ps1 doctor --json` first. Do not download or install FFmpeg, ffprobe, Real-ESRGAN, RIFE, or any other dependency. If a selected feature needs a missing tool, report the doctor's recommendation and ask the user to approve installation through the desktop app.
2. Run `inspect --input <video> --json`. Report the source dimensions, frame rate, frame-rate mode, frame count, duration, codec, color information, and audio tracks before processing. JobSpec v4 requires `frameRateMode: "constant"`; ask the user to convert a variable-frame-rate source to CFR before frame-accurate trimming.
3. Resolve only choices that inspection cannot determine. Honor explicit user choices; otherwise use the defaults below. Select an exact source frame range; if no trim is requested, use `{ "startFrame": 0, "endFrameExclusive": <inspected frameCount> }`. Ask before overwriting or choosing a materially different output location.
4. Prefer a `JobSpec v4` JSON file outside the skill directory when `doctor.capabilities.jobSpecVersions` contains `4`. v4 requires `sourceRange` and explicit nested `upscale.backend/model` plus `interpolation.backend/model`. Use v3 with an older CLI that supports `3`, and v2/v1 only when necessary; v1/v2 always process the complete source.
5. Keep temporary frames and resumable state in `<output-directory>/.ai-video-wallpaper-work` by default. When the user chooses another volume, pass the same absolute `--work-dir <path>` to preview, diagnostic preview, and process. Pass cache policy and limit deliberately; default to `cleanup-on-success` and 50 GiB.
6. Run a representative segment preview before an expensive AI job: `preview --config <job.json> --preview-mode segment --center <absolute-source-seconds> [--work-dir <path>] --json`. Omit `--center` to use the selected range midpoint. Omit `--frames` for the default of about two seconds, calculated from the inspected source FPS rather than a fixed 48 frames. Show the preview path. For RIFE, report input and output FPS and inspect fast motion, text, particles, occlusion, and cuts; for Real-ESRGAN, inspect temporal texture flicker.
7. Preview the loop behavior separately. For `pingpong`, run `preview --config <job.json> --preview-mode loop-boundary --turn end ...` and use `--turn start` when the other reversal also needs inspection; omitting `--turn` defaults to `end`. For `loopMode: none`, run `--preview-mode loop-boundary` without `--turn` to inspect the direct tail-to-head seam. Never combine a boundary preview with `--center`.
8. After the user accepts the previews, run `process --config <job.json> [--work-dir <path>] --json`. Preserve each JSON Lines progress event and the final result. Forward Ctrl+C for cancellation; rerunning the identical config with the same work directory resumes reusable work.
9. Run `verify --input <output> --expected <expected.json> --json`. Require `sampleAspectRatio: "1:1"`. Verification performs a complete FFmpeg decode and reports catastrophic black/frozen output checks in addition to metadata. Return the output path, dimensions, square-pixel SAR, frame rate, frame count, duration, codec, pixel format, BT.709 status, audio status, decode health, and whether every check passed.
10. When the user needs a quality diagnosis, run `diagnostic-preview` for the same segment or loop boundary. It accepts the same `--preview-mode`, `--turn`, `--center`, and `--frames` rules as `preview`; omit `--center` on a segment to scan the selected source range and auto-locate the highest-priority review risk. Compare A Lanczos, B AI 2x, C AI 3x, and D RIFE 2x plus AI 2x using each variant's elapsed time, cache bytes, media properties, and visual result.
11. When the user wants a fast loop comparison, run `loop-preview --config <job.json> --output-dir <path>`. It generates the ping-pong end turn, ping-pong start turn, and direct seam together at a maximum 960-pixel long edge. It deliberately skips Real-ESRGAN and RIFE; use a normal `preview` afterward for a final-effect check with the complete JobSpec.

## Defaults

- Use `2560x1600` for this user's current display unless the user requests `2560x1440`, `3840x2160`, or another even-sized target.
- Use `cover` (crop-to-fill), centered focus `{ "x": 0.5, "y": 0.5 }`, and `pingpong` by default. Select `blur-background` only when preserving the complete frame matters more than avoiding a generated background.
- In standard mode use `realesrgan-ncnn-vulkan`, model `realesr-animevideov3`, and tile `384` for anime or illustration. Use the `lanczos` backend when temporal stability, speed, or lack of a Vulkan GPU matters more than invented detail.
- Use `gpuId: "auto"`, `aiScale: "auto"`, and `batchSize: 64`. Automatic AI scale is conservative: it bypasses AI entirely when the source already covers the target, otherwise it chooses the lowest supported scale whose remaining Lanczos enlargement is no greater than 1.20. Thus `1136x800` to `2560x1600` cover uses AI 2x. Lower the batch size to `32` when a driver or filesystem struggles with larger Real-ESRGAN directory batches.
- Keep interpolation off unless the user requests smoother motion or accepts it after preview. Standard mode uses `rife-ncnn-vulkan` with `rife-v4.6`, automatic memory mode, and hold protection. Exact duplicate frames are held automatically; two-/three-frame cadence, near duplicates, flashes, dissolves, text/particles, and high variation remain review-only risks in `frameRiskAnalysis`. Prefer 24 to 48 fps and 30 to 60 fps; do not silently force 24 to 60 fps.
- Use source FPS `auto` and fixed H.264 output metadata: High profile, yuv420p, BT.709, and no audio. Default to `libx264` CRF 17 slow for quality and smaller files. Use `h264_nvenc` p6/HQ/VBR/CQ 17 only when the user explicitly selects faster encoding and accepts a larger file; JobSpec never contains encoder `auto`.
- The v0.4.5 desktop preserves occupied final outputs by selecting the next available `name (N).mp4` path and rechecking immediately before processing. Direct CLI jobs remain strict: choose a different output path yourself when `E_OUTPUT_EXISTS` is returned.

## Guardrails

- Treat `pingpong` as continuity without duplicated endpoint frames, not as optical-flow seamless motion. Motion reverses at each turn.
- Treat ComfyUI LTX and Wan 2.2 workflows as upstream candidate generators. This v0.4 processor accepts their exported video files but does not connect to ComfyUI, submit workflows, or generate source clips itself.
- Do not claim frame-accurate selection unless `frameRateMode` is `constant`. v0.4 rejects JobSpec v3/v4 ranges for both `variable` and `unknown`; convert the source to CFR first, then inspect it again and select the new frame range.
- Never stretch the image. Confirm that `cover` cropping is acceptable; use `contain` for black bars or `blur-background` when the complete frame must remain visible.
- Reject `h264_nvenc` when either target dimension exceeds 4096. Offer an aspect-preserving size such as `4096x2560` for a `5120x3200` target or an explicit `libx264` choice; never silently change it.
- Treat RIFE as synthesized motion, not recovered source frames. It can warp occlusions, particles, text, flashes, and cuts, and it cannot reconstruct motion hidden by duplicate source frames. Require a representative preview.
- Do not accept a partial benchmark. Require all three benchmark groups; paired LPIPS/DISTS, warp-residual, motion-compensated temporal error, and SSIM for every ground-truth case; candidate VRAM, peak work/cache disk, and hard-cut results for every case; and candidate elapsed time from the unique 30-second `runtimeCaseId`. The report and approval must bind the same exact profile, `runtimeManifestSha256`, and `runtimeLockSha256`.
- When both RIFE and AI upscaling are enabled, warn that interpolation may amplify trails, double lines, and occlusion errors. When target linear enlargement exceeds 2.0, warn that eyes, hair, and fine lines may be reconstructed and recommend a 1080p source or conservative mode.
- Do not assume a successful process leaves reusable frames. Under the default policy, cleanup happens only after encode, FFprobe verification, atomic publish, active-cache release, and job-lock release. Failed, cancelled, and preview caches remain recoverable for 24 hours.
- Never fabricate detail claims. Compare the preview at 100% scale and mention that Real-ESRGAN improves perceived edges and texture but cannot recover information absent from the source.
- Never copy, load, convert, wrap, download, or integrate proprietary VideoProc Converter AI, Digiarty, or Aiarty models, configurations, executables, or DLLs. Use only project-supported models whose license permits the requested use.
- Never invoke a shell command assembled from user text. Pass every CLI token as a separate wrapper argument.
